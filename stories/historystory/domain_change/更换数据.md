好问题——这个项目在设计时已经把"朝代内容"和"渲染引擎"分离了，换专题基本只动**数据定义**，不动渲染代码。下面按修改顺序说明：

## 一、核心要改的三处内容（都在 preprocess.py 顶部）

**1. 势力表 FACTIONS**
把商代 10 个势力换成新专题的势力。每个势力需要：id、名称、代表色。比如战国专题就是齐、楚、燕、韩、赵、魏、秦、周王室、越、中山等。附庸浅色（vassal_color）是管线自动从主色生成的，不用手配。
建议：势力数量控制在 8–12 个以内，颜色要在暗夜底图上互相分得开（金/朱/青/紫/灰绿这类低饱和色系效果最好）。

**2. 城池表 CITIES**
每座城需要：id、名称、经纬度、初始归属势力、是否都城。这是唯一需要**手动考据坐标**的部分——历史城池的现代经纬度可以从《中国历史地图集》或维基百科查到，近似即可（地图上会吸附到所在县）。
建议：20–40 座城比较合适，覆盖所有势力的都城 + 关键战场（如长平、桂陵、马陵）。

**3. 事件表（data_raw/events_src.json）**
这是专题的灵魂。每个事件包含：
- 年份、标题、摘要、《史记》（或《战国策》《左传》）原文引文和出处
- 事件类型：占领 / 灭国 / 联盟 / 反叛 / 归附 / 决战 / 称制 / 迁都 / 继位 / 出征 / 决裂（每种类型已有专属动画，直接用）
- 结果（outcomes）：谁占了哪座城、谁灭了谁、谁成为谁的附庸——管线会把城池归属换算成**县级疆域增量**

西周专题约 270 年，战国约 250 年，都比商代 550 年事件密度高，建议每专题选 **15–25 个关键事件**（如西周：武王克商、周公东征、分封诸侯、国人暴动、平王东迁；战国：三家分晋、田氏代齐、商鞅变法、合纵连横、长平之战、秦灭六国）。

## 二、UI 文案微调（index.html）

只需改几处文字：左上角标题"山河裂变"下的副标题（现在是"先秦 · 战争与疆域实录"）、初始年份显示。所有事件卡内容、势力图鉴、年份轴都是**从数据自动生成**的，不用改 HTML。

## 三、不需要动的部分

- **地理底图**（高程、海岸线、水系、2874 县界）：全国通用，直接复用，不用重新烘焙
- **渲染引擎 main.js**：完全数据驱动
- **管线主体逻辑**：四阶段流程不变

## 四、操作流程

1. 复制一份项目目录（data/ 里的 heightmap、counties.bin、county_lines、geo 可以保留，删掉 timeline、boundaries、cities、factions 让管线重新生成）
2. 改 preprocess.py 的势力/城池表 + 写好新的事件 JSON
3. 重跑 `python3 tools/preprocess.py`（只跑 replay 阶段的话几分钟，全量重跑约十几分钟）
4. 起服务打开即是一个新专题

## 两个实操建议

- **分封制处理**：西周大量"封建"事件，用"归附/联盟"类型表达诸侯与周王室的关系最合适——附庸会自动并入宗主轮廓、用浅色填充，正好呈现"宗周—封国"的层级；诸侯独立时用"决裂/反叛"
- **战国七雄并立**：这种多强对峙的格局是本项目最出效果的场景——七国连片色块互相蚕食，长平、灭国大战的"面积崩塌"会非常有视觉冲击力
