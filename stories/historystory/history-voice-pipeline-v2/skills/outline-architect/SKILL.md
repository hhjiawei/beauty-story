# 历史旁白大纲生成（起承转合·关系驱动）

把素材卡转化为一篇逻辑闭环的旁白大纲。三条铁律：

1. **关系先于段落**——先构建四要素关系层，段落是关系的容器；大纲禁止出现无关系的素材。
2. **相位固定，段数弹性**——起承转合必须各出现；每相位内部要几段，由关系类型与意图单元推导，禁止写死段数。
3. **每张卡有去向**——用卡 100% 落到段落，封存卡 100% 有理由；没有无主之卡，也没有无卡之段。

**本技能只产出大纲，不写正文。** 段意与备注只写施工指令，禁写正文句子。目标时长未指定时默认 20 分钟（×270 字/分钟 ≈ 5400 字）。

## 输入规范

### 标准输入：素材卡数组（JSON）

每张卡是一个带类型的史料单元，六种卡型：

| 卡型   | 编号前缀 | 用途                     | 必填字段                                                       |
| ------ | -------- | ------------------------ | -------------------------------------------------------------- |
| 事件卡 | C-       | 有冲突、有动作的历史节点 | 卡号、卡型、时间、地点、人物、冲突、史料出处、可信度           |
| 人物卡 | P-       | 篇中人物                 | 卡号、卡型、人物名、身份、核心特质、史料出处、可信度           |
| 关系卡 | R-       | 双方张力与演化           | 卡号、卡型、双方、关系性质、张力点、演化                       |
| 背景卡 | B-       | 制度/地缘/时代机制       | 卡号、卡型、主题、要点、史料出处、可信度                       |
| 数据卡 | D-       | 数字托底                 | 卡号、卡型、指标、数值、对比基准、史料出处、可信度、备注       |
| 彩蛋卡 | E-       | 歇后语/梗/氛围素材       | 卡号、卡型、类型、内容、挂接事件、建议用法                     |

约定字段（各卡通用）：

- `本集用不用`：用 / 封存 / 待定——"封存"卡不进段落，但仍须登记进卡片消费闭环表；
- `古文原句`：凡可引原文一律照录，大纲备注列直接使用；
- `可信度`：正史 / 野史 / 孤证 / 存疑——孤证与存疑卡挂接时必须在备注标"存疑须声明"。

### 非标准输入

用户直接粘贴史料原文或散述 → 先**卡片化**：通读后拆解为上述六类卡、编号、请用户确认，再进入流程。禁止跳过卡片化直接写大纲。

## 主流程（S0–S6 逐步执行，每步有产出与验收）

### S0 卡片清点与初筛

**动作**：
1. 遍历卡片，按六卡型归类计数。
2. 核对约定字段；孤证/存疑卡打标。
3. 初筛封存（两级判据）：①挂不上主线 → 封存，标去向（删除/未来篇目）；②好看但不推进论点 → 同样封存。封存判据在 S1 之后复核一遍（主线命题确定后可能有卡翻案）。
4. 缺卡预警：C 卡 < 3 → 主线撑不起来，报"需补事件卡"；B 卡 < 2 → 转只能选叙事转折型；D 卡 = 0 → 篇内宏大判断须降调为具体事例，或标"需补数据卡"。

**产出**：卡片清点表（卡型 × 数量）＋封存候选清单。
**验收**：每张卡状态明确（用/封存/待定）。

### S1 关系层构建 【核心步骤】

**动作**（细则见 references/relationships.md）：
1. **定根**（归属关系）：本篇以谁为根——人物篇事归于人，事件/风气篇人归于背景。换主角或换朝代本篇仍成立 → 根定错了。
2. **列主体对**：从用卡列出全部要素主体对（人-人、人-事、事-事、事-背景、人-物、人-背景）。
3. **挂关系类型**：逐对按判定法标关系（一对可多标）；R 卡直接转写为主体对＋关系类型，其"演化"字段即演化关系。
4. **排主线关系链（spine）**：选出从起能贯通到合的一条关系序列作为主线；其余关系作为支线挂靠主线节点，不另起炉灶。

**产出**：关系链清单（主体对＋关系类型＋挂卡号）。
**验收**：每张用卡至少挂在一条关系上（挂不上 → 回 S0 封存）；每处标"因果"的都写得出一句机制句；主线重大因果全部过跨度检查（中间变量＋强度）。

### S2 主线命题与转形态选型

**动作**：
1. 从主线关系链提炼**核心矛盾**：表层关系（观众以为的解释）vs 深层关系（本篇要立起的解释），两句话缺一不可。
2. 压缩成**一句话主线**（可证伪）：翻案型用"不是【表层】，而是【深层】"；人物历程型用"他凭什么/靠什么___"。
3. **转形态选型**（一旦选定不得中途换）：≥2 张 B 卡指向同一机制 → 结构归因型；B 卡不足 → 叙事转折型。判据写入篇级总表。

**产出**：核心矛盾＋一句话主线＋转形态选型（含判据）。
**验收**：一句话主线可证伪；全篇素材取舍若失去标尺即不成立——它就是唯一标尺。

### S3 四相位任务分配

**动作**（各相位执行规程、段数判定与禁区见 references/phase-paragraphing.md）：
1. 起承转合各写一句任务书（该相位完成的关系动作）。
2. 选起形态（现象蒙太奇式 / 报幕定调式）与合形态（阴冷 / 幽默回扣 / 盖棺判词 / 远期伏笔）。
3. 起的任务锁定为：**核心矛盾的现象描述**——只呈现现象，不解释、不铺年代背景。

**产出**：四相位任务书＋形态选型。
**验收**：四句任务连读＝全篇逻辑；起的任务书内不含任何解释性动作。

### S4 分段推导与段落表填写

**动作**：
1. 逐相位按分段判定推导段落数（见 phase-paragraphing.md：意图单元、关系类型切换、引出方式）。
2. 按模板（assets/outline-template.md）填段落表，每段必填：段意、关系类型（从 S1 清单直接抄，不另发明）、挂卡、情绪坐标、引出方式、段尾欠条、预计字数。
3. **情绪坐标逐段必填**（戏谑/悲悯/热血＋强度 _/5）：相位定基调，苦难/殉国/冤死段标【悲悯】——情绪是大纲结构的一部分：写作层照此兑现，装配层照此设禁区，画本层照此翻译；本列由大纲产出，下游无权改。
4. **引出方式逐段填写**（问答/因果/递进/镜头/时间五种）——写不出引出方式的段＝不该存在的段，删。
5. 思考顺序建议：先推转的骨架 → 再定承的峰值 → 再回头定制起 → 最后写合；输出文档仍按起→合排列。

**产出**：完整段落表。
**验收**：每段段意一句话说得清（说不清＝装了多个意图，拆段）；字数合计＝预算 ±10%。

### S5 卡片消费闭环

**动作**：逐卡登记去向（段号＋用途：关系例证 / 数字托底 / 古文直引 / 氛围调味）；封存卡登记理由与去向；"待定"卡在此必须二选一（用/封存），不许带出大纲阶段。

**产出**：卡片消费闭环表。
**验收**：用卡 100% 出现在段落表挂卡列，且用途精确；段落表无凭空卡号；封存卡 100% 有理由。

### S6 质检与输出

**动作**：
1. 过 assets/outline-template.md 末尾的质检清单（逐条打勾）。
2. 运行机检脚本（FAIL 项修完复检）：

```bash
python skills/outline-architect/scripts/check_outline.py <大纲.md> --minutes <分钟数> --cards <素材卡.json>
```

3. 按模板组装大纲文档，写入输出目录，文件名"标题-大纲.md"。

**产出**：最终大纲（Markdown，段落表制，机检全绿）。
**验收**：质检清单全过；通读段落表"段意"列（不看其他列）自成一篇缩略论证。
